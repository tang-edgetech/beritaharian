News, directory and civic reports for Melaka

One platform that tells locals and tourists what is happening, where to go, and what has been verified as true. This page sets out the stack, how the parts fit together, the data model, and the decisions still open.

Daily newsEditorial articles, alerts and live updates, fact-checked before publishing.
Business directoryYellow-pages listings from hawker stalls to hotels, with reviews and paid pins.
Civic reportsPublic incident reports, verified by staff, exportable as evidence for PDRM.
Stack decisions

Three apps, one API

Laravel is the only thing that talks to MySQL. The public site, the admin panel and the future mobile app all consume the same versioned REST API (/api/v1). This is what makes the mobile app cheap later: no new backend.

PartChoiceWhy
Public siteNext.js (App Router) + TailwindServer rendering for Google indexing of news and listings; ISR so popular pages are cached HTML.
Admin panelNext.js + Tailwind + shadcn/uiSee the decision below. Runs as its own Node.js app on cPanel.
BackendLaravel (latest) + MySQL 8API only. Sanctum auth, queues, scheduler, policies, events.
Future mobileExpo (React Native)Shares TypeScript types, validation schemas and API client with both Next.js apps.
Recommendation: shadcn/ui instead of Ant Design for the admin

Ant Design v5 styles itself with CSS-in-JS. That is exactly where class names like .css-dev-only-do-not-override-u6izyw and .css-var-_R_5b_ come from. You can turn hashing off, but you will keep fighting it, and its look is instantly recognisable.

shadcn/ui is copied into your own codebase as plain React + Tailwind files built on Radix primitives. Every class is a Tailwind utility or a name you wrote. It covers dialogs, tooltips, dropdowns, tabs, forms, command palette and data tables, and it has no fixed visual identity, so the Dribbble-led design is yours to apply.

Companion libraries: TanStack Table (sorting, filtering, bulk selection, pagination), dnd-kit (drag to reorder), Sonner (toasts), React Hook Form + Zod (forms), Lucide (icons), TanStack Query (API cache).

Why not the admin in Laravel (Filament / Blade)?

It is faster to build, but you would maintain two UI stacks, two design systems and two naming conventions. With both front ends in Next.js, components such as the listing table, filter bar and rating stars are written once in a shared package.

Roles & access

Who can do what

Roles are bundles of permissions (via spatie/laravel-permission), so new roles can be created in the admin without code changes. "Own" means only records they created or businesses they manage.

A person can hold several roles. A journalist can also own a business; a verifier can never verify their own submission (enforced in policy, not just the UI).

Finance (added with billing): views billing, prepares invoices, records payments and expenses, prints reports. Confirming payments, voiding invoices and issuing credit notes need the separate approval permission, held by admins and super admins.

Data model

Relational core, document-shaped details

MySQL 8 gives us both worlds. Things we join, filter and count (users, businesses, articles, ratings) are proper columns with foreign keys. Things that vary by type are JSON documents inside the row, so a hotel and a hawker stall share one businesses table without 80 empty columns.

Object-oriented: Eloquent models
  • Every table maps to one model class with relations, casts and policies.
  • Polymorphic relations: one media, reviews, verifications, reports and pins table serves many owners.
  • Public IDs are ULIDs, so URLs never expose row counts.
  • Soft deletes and timestamps on every business table.
Document-oriented: JSON columns
  • title, body, name stored as {"en":…, "ms":…, "zh":…}. English at launch; BM and Chinese are filled in later with no schema change.
  • businesses.details holds sector-specific fields (halal, cuisine, star rating...), checked against the field list stored on the sector. Moderators build that list in the admin; fields marked as filters become reader filters.
  • Fields we filter on (e.g. halal) get a generated column + index.
  • settings.value, media.meta, evidence.exif are documents.

UI rules

Standards every screen follows

Listing pages

One reusable DataListing component drives every list in the admin, so all of them behave the same:

  • Checkbox column with select page / select all matching, and a bulk action bar that appears on selection.
  • Search box, filter drawer (status, date range, area, author…), active filters shown as removable chips.
  • Sortable column headers, column show/hide, items per page (10, 25, 50, 100), pagination with total count.
  • Filters, sort and page are kept in the URL query string, so a filtered list can be bookmarked or shared.
  • Row actions as icon buttons with a tooltip on hover (Edit, View, Duplicate, Delete).
  • Export to CSV for the current filter. Empty and loading states designed, not blank.

The API returns a machine code (ARTICLE_NEEDS_VERIFICATION) and the front end maps it to a sentence in the user's language. Stack traces and SQL errors never reach the screen; they go to the system log.

Pages over popups

Create and edit forms are full pages with their own route. Popups are used only for confirmations and quick pickers. Reordering (categories, sectors, plans, pinned slots, gallery photos) uses drag and drop with a save toast.

Class naming

Readable class names next to Tailwind

Each element carries one human name that says what it is, followed by Tailwind utilities. Names are kebab-case: block, then part (news-card, news-card-title). States use an is- or has- prefix. IDs only for anchors and form fields.

Maps: free first, Google Maps when it pays for itself

  • Now: Leaflet with OpenStreetMap tiles. Free, no key, many custom pins, pin clustering, "near me". The free Google Maps embed is not used because it shows only one place or one search per map.
  • If traffic grows before revenue: switch the tile source to a hosted free plan (for example MapTiler), since the public OpenStreetMap tile server is meant for light use.
  • Later: Google Maps JavaScript API and Places, set in Settings › Extra. All map code sits behind one MapView component and one geocoding service, so the switch touches those two places only.
  • Locations are stored as plain latitude and longitude (spatial columns), never tied to a provider's place ID, so data survives a provider change.
Design direction

Your moodboard leads, not a template

The look should come from references you choose. Proposed process:

  1. You collect 5 to 10 shots you like from Dribbble, Behance, Mobbin (real app screens), Refero, Godly, Awwwards, Land-book or Httpster. Useful searches: "editorial news web", "city guide app", "local directory", "magazine layout", "admin dashboard data table".
  2. For each shot, note what you like: the type, the colour, the grid, the card style, the motion.
  3. I turn that into design tokens (colour, type scale, spacing, radius, shadow) in packages/ui, plus a component sheet you approve before any page is built.

Ideas specific to Melaka to bring into it: Peranakan tile patterns as section dividers, the colours of Jonker Street shophouse fronts, the Melaka River at night for a dark theme, and area chips named the way locals say them (Bandar Hilir, Klebang, Ayer Keroh).

About "dozens of thousands of users"

MySQL and Laravel handle that comfortably. The weak point is shared cPanel hosting: limited Node processes, CPU throttling, no Redis, no long-running workers. Plan to move to a VPS (still with cPanel/WHM if you like) before a big tourism season or a viral news day. The code above needs no change for that move.

Legal & evidence

Handling reports and personal data responsibly

  • PDPA 2010: privacy notice and consent at registration and report submission, data export and account deletion on request, retention periods per data type.
  • Evidence integrity: original uploads are never edited. Every file gets a SHA-256 hash at upload; published versions are separate blurred copies. The export includes a manifest so police can confirm nothing changed.
  • Police handover: the platform prepares an evidence pack and logs the handover. A direct link into PDRM systems would need an agreement with them, so treat that as a later conversation.
  • Defamation risk: incidents naming people or businesses stay private until verified; public alerts describe events, not accusations.
  • Reviews: owners can reply and report a review, but cannot delete it. Paid businesses get no ranking boost in reviews, only in clearly labelled "Sponsored" slots.

WhatsApp is not free for one-time codes

The official WhatsApp Business Cloud API from Meta charges per authentication message, and needs a verified Meta Business account and an approved message template. The "free WhatsApp API" libraries online work by automating a personal WhatsApp login, which breaks WhatsApp's terms and gets numbers banned, so we won't use them. Launch with email codes (free), and add WhatsApp when the per-message cost is acceptable.

Built ahead of schedule: invoicing and light bookkeeping

The Billing phase is in the admin panel now (Finance section), so every ringgit is recorded properly from day one. It is not a full accounting system; it keeps formal records and prints them.

  • Customers with registration, tax and address details; archive instead of delete.
  • Invoices: draft, issue (number given and locked), partly paid, paid, credited, void. Overdue is worked out from the due date. Drag lines to reorder; copy an invoice as a new draft.
  • Payments and refunds: recorded against an invoice, checked against the bank statement, then confirmed. Confirming gives the receipt or refund-voucher number. Bulk confirm on the Payments page.
  • Credit notes reduce an issued invoice; a refund follows if the customer had already paid.
  • Expenses with the supplier's bill attached, kept privately.
  • Reports: Sales, Money received, Outstanding (by how late), Income and expenses (cash basis, by month and category), Expenses, Tax charged, and a Statement of account per customer. Each shows on screen, prints, downloads as an A4 PDF and exports as CSV for the accountant.
  • Formal documents: invoice (or tax invoice once SST is on), official receipt, refund voucher, credit note. Each has the logo, company details, both parties, amount in words, page numbers, and VOID / PAID stamps where they apply.
  • Who can do what: billing.view, billing.manage (prepare), billing.approve (confirm payments, void, credit notes), billing.reports. A new Finance role prepares and prints but needs an approver to confirm money, so no one person both records and approves.
  • Settings: Company tab (name, SSM, TIN, SST, address, bank) and Billing tab (number prefixes, payment terms, tax on/off and rate, standard wording, expense categories).

Receive money through a registered business

Before the first paid customer: register a sole proprietorship (or a partnership, if there are co-founders) with SSM through EzBiz Online, open a business current account in that name, and declare the profit as business income in the owner's personal tax return. Move to a Sdn Bhd when starting officially, because a news and user-content platform carries defamation and PDPA risk that a company keeps away from personal assets. Confirm Service Tax, e-invoicing timing and audit needs with a Malaysian accountant or company secretary.
